Pipeline

Do commit ao deploy

Cada alteração percorre o mesmo caminho automatizado, auditável e reversível.

Arraste o diagrama para o lado para ver tudo.

  1. CommitO dev envia o código para a branch e abre um pull request.
  2. RevisãoCode review e checks obrigatórios antes do merge no GitHub ou GitLab.
  3. CIO pipeline compila, roda testes, SAST e análise de dependências.
  4. ImagemA imagem é construída, escaneada e publicada versionada no Amazon ECR.
  5. HelmO pipeline autentica na AWS por OIDC, sem chaves estáticas, e aplica o chart com os values do ambiente.
  6. RolloutO cluster faz rolling update com health checks e rollback automático em caso de falha.
Arquitetura

Do usuário ao pod, com segurança em cada camada

Redes públicas só para a borda (API Gateway e Load Balancer). O cluster EKS, a malha Istio, o banco e a telemetria ficam em redes privadas. O mesmo desenho vale para AKS, com os serviços equivalentes da Azure.

Arraste o diagrama para o lado para ver tudo.

  1. DNS e bordaO usuário acessa a URL. O DNS resolve para o CloudFront, com TLS 1.3 e proteção Shield.
  2. WAFO AWS WAF bloqueia ataques do OWASP Top 10, bots e abuso com regras e rate limit.
  3. API GatewayValida o token JWT, aplica throttling e encaminha para a VPC por um VPC Link privado.
  4. Load BalancerO ALB ou NLB fica nas subnets públicas e só aceita tráfego do API Gateway.
  5. Istio GatewayEntra nas subnets privadas pelo ingress do Istio (Envoy), com AuthorizationPolicy e validação de JWT.
  6. Malha de serviçosCada pod tem um sidecar Envoy. O tráfego entre serviços usa mTLS STRICT e NetworkPolicy.
  7. Dados e telemetriaOs serviços acessam o RDS em rede privada, e o Datadog ou ELK coletam logs, métricas e traces.
